# Protocol: the audit thread

The thread is where the agents of one audit mission talk to each other, and
because it is made of files it is also the record. What is not in the thread
did not happen. The mechanism is `tools/thread.py`.

## Layout

`<root>/threads/<YYYY-MM-DD>_<key>/`

- `thread.json`: header with key, mission, coordinator, target, content hash
  of the target, token budget, opened and closed timestamps.
- `posts/<HHMMSS>_<agent>.md`: one file per post, written by its author through
  `thread.py post`. Nobody edits another agent's post.
- `SYNTHESIS.md`: written only by the thread coordinator, at most 15 lines,
  rewritten every round. It cites each relevant post by id with a state:
  accepted, refuted, pending or out of scope.
- `THREAD.md`: generated by `thread.py render`; never edited by hand.

## Post

```
---
id: 184512_data-provenance
agent: data-provenance
to: coord-data             # vertical; another front = lateral; "coordinator"
reply_to: 183900_coord-data   # optional
artifact: <path>           # mandatory, must exist
tokens: 0                  # optional; agents rarely know their own usage
severity: block | warn | info # optional
supports_claim: true       # optional
---
At most 200 words: what was done, what was concluded, what is asked of whom.
```

## Who reads what

- A front reads `## Synthesis` and `## Open questions` of its own thread,
  never the whole thread.
- A coordinator reads the synthesis and the artifacts of its fronts, never raw
  material. `## Posts not absorbed by the synthesis` lists what the synthesis
  does not yet cite.
- Blind roles (for example an independent re-implementer) do not read the
  thread at all.

## Rules with a mechanism

| rule | mechanism |
|---|---|
| one open thread per key | `open` refuses a key that is already open |
| no re-audit of an unchanged target | `open` refuses a target whose content hash is already in `audited_targets.jsonl`; `--force "reason"` records why |
| posts are short, detail goes to the artifact | `post` refuses more than 200 words and a missing artifact |
| nothing blocking is forgotten | `check` fails if a post with `severity: block` or `supports_claim: true` is not cited in the synthesis, if an artifact is missing, or if the synthesis was never written |
| a closed thread is closed | `close` requires a clean `check`, records the target hash, and later posts are refused |
| budget is visible | `total` reports tokens against the budget; at 80% the coordinator stops or asks for more |

Live messages between agents, when the runtime allows them, are mirrored as a
post by the sender, so that the record stays complete.
